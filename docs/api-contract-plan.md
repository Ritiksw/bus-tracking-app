# Shared API Contract Plan

## 1. Approach
- Author API contract with OpenAPI 3.1, describe backend endpoints, schemas, security.
- Source of truth in `backend/src/main/resources/openapi.yml`; generated by SpringDoc at runtime and committed as baseline.
- Use [openapi-generator](https://openapi-generator.tech/) for Angular SDK (`typescript-angular`) and Java clients (for integration tests).
- Introduce contract validation in CI: backend unit test asserts SpringDoc output matches committed spec, frontend generation step verifies build.

## 2. Iterative Workflow
- **Design first**: model endpoints/DTOs in `openapi.yml`, review with stakeholders.
- **Backend**: implement controllers/services per spec; leverage SpringDoc annotations for changes, regenerate spec via `mvn springdoc-openapi:generate`.
- **Frontend**: run `npm run generate:api` script (to be added) that calls openapi-generator and updates Angular SDK in `src/app/api`.
- **Contract testing**: backend integration tests use generated Java client; frontend uses SDK types for compile-time safety.

## 3. Endpoint Groups
- `Auth`: login, refresh, logout, token revoke.
- `Admin`: manage users, roles, buses, routes, stations.
- `Trip`: create trip, list, get details, segment lifecycle mutations.
- `Telemetry`: batch GPS ingestion, retrieve recent pings.
- `Notifications`: register WebSocket/SSE subscriptions, fetch notification preferences.
- `Audit`: query audit trail, export summary.

## 4. Key Schemas
- `User`, `Station`, `Route`, `RouteSegment`, `Bus`.
- `Trip`, `TripSegment` with status enums (`PENDING`, `REJECTED`, `APPROVED`, `IN_TRANSIT`, `ARRIVED`).
- `GpsPing` with `capturedAt`, `receivedAt`, deduplication key.
- `NotificationMessage` with polymorphic payload.
- `AuditEvent`.

## 5. Security & Headers
- Global bearer auth requirement with JWT.
- Include optional `X-Client-Version` for offline clients, validated by backend.
- Standard paginated responses using `page`, `size`, `totalElements`.

## 6. Tooling Tasks
- Add Maven plugin (`springdoc-openapi-maven-plugin`) for spec generation.
- Configure `package.json` script for TypeScript client generation (requires `@openapitools/openapi-generator-cli` dev dep).
- Create GitHub Action step to fail if generated artifacts differ from committed spec.
